## 简介
本文件全面文档化了系统的多语言支持机制。系统通过后端配置与前端上下文管理相结合的方式，实现了用户界面的国际化（i18n）和本地化。核心配置文件 `lang.json` 定义了系统支持的语言及其显示名称，而前端的 `LanguageContext.tsx` 则负责动态管理当前语言状态。系统设计了完善的容错机制，确保在配置文件缺失或损坏时仍能正常运行。此外，系统还确保了生成的维基文档语言与用户界面语言的一致性。

## 核心语言配置

系统的核心语言配置由 `api/config/lang.json` 文件定义，该文件通过 `config.py` 中的 `load_lang_config()` 函数进行加载。此配置文件是系统多语言支持的基础。

**Section sources**
- [lang.json](file://api/config/lang.json)
- [config.py](file://api/config.py#L233-L259)

### 支持的语言定义
`lang.json` 文件中的 `supported_languages` 对象定义了系统支持的所有语言。该对象是一个键值对映射，其中：
- **键（Key）**：为语言代码（如 `en`, `zh`, `ja`），这些代码遵循ISO 639-1标准。
- **值（Value）**：为该语言的显示名称，通常包含英文名称和括号内的本地化名称（如 `"Mandarin Chinese (中文)"`）。

```json
{
  "supported_languages": {
    "en": "English",
    "ja": "Japanese (日本語)",
    "zh": "Mandarin Chinese (中文)",
    "zh-tw": "Traditional Chinese (繁體中文)"
  }
}
```

### 默认语言设置
`lang.json` 文件中的 `default` 字段用于设置系统的默认语言。当系统无法确定用户首选语言时（例如，首次访问或浏览器语言不被支持），将自动使用此默认语言。在当前配置中，`"default": "en"` 表明英语是系统的默认语言。

## 配置加载与容错机制

系统的配置加载机制由 `api/config.py` 文件中的 `load_lang_config()` 函数实现，该函数设计了强大的容错能力，确保系统在各种异常情况下仍能稳定运行。

### 容错逻辑详解
1. **文件缺失处理**：`load_lang_config()` 函数首先尝试加载 `lang.json` 文件。如果文件不存在或无法读取，函数会直接返回一个内置的默认配置对象，避免了因配置文件缺失而导致的系统崩溃。
2. **配置损坏处理**：即使文件存在，也可能因格式错误或内容不完整而损坏。该函数会检查加载的配置是否包含必需的 `supported_languages` 和 `default` 字段。如果任一字段缺失，函数会记录一条警告日志，并同样返回内置的默认配置。
3. **默认配置**：内置的默认配置与 `lang.json` 文件中的内容完全一致，包含了所有支持的语言和默认语言设置，确保了用户体验的一致性。

## 前端国际化实现

前端的国际化（i18n）功能由 `src/messages` 目录下的语言包文件和 `src/i18n.ts` 文件共同实现，为用户界面提供了多语言文本支持。

**Section sources**
- [i18n.ts](file://src/i18n.ts)
- [messages](file://src/messages)

### 语言包文件
`src/messages` 目录下存放着每个支持语言的JSON文件，如 `en.json`、`zh.json`、`ja.json` 等。这些文件是实际的翻译资源库，其结构通常为嵌套的对象，将文本的键（key）映射到对应语言的翻译值（value）。

例如，`zh.json` 文件定义了中文界面的文本：
```json
{
  "common": {
    "appName": "DeepWiki-Open",
    "tagline": "AI驱动的文档"
  },
  "home": {
    "welcome": "欢迎使用DeepWiki"
  }
}
```

而 `en.json` 文件则提供了英文翻译：
```json
{
  "common": {
    "appName": "DeepWiki-Open",
    "tagline": "AI-powered documentation"
  },
  "home": {
    "welcome": "Welcome to DeepWiki-Open"
  }
}
```

### 国际化配置
`src/i18n.ts` 文件定义了系统支持的区域设置（locales），并导出了一个 `getRequestConfig` 函数。该函数在服务器端被调用，根据请求的 `locale` 参数动态加载相应的语言包文件，实现了服务端渲染（SSR）的国际化支持。

```typescript
export const locales = ['en', 'ja', 'zh', 'es', 'kr', 'vi', 'pt-br'];
```

### 核心功能
1. **初始化与加载**：
   - 组件首先通过 `fetch('/api/lang/config')` 从后端获取最新的 `supported_languages` 和 `default` 配置。
   - 如果后端请求失败，它会优雅地降级到一个内置的默认语言列表。
2. **语言检测与持久化**：
   - 在加载语言包时，组件会优先检查 `localStorage` 中是否存储了用户之前选择的语言。
   - 如果没有，则调用 `detectBrowserLanguage()` 函数，根据浏览器的语言设置自动选择一个最匹配的受支持语言。
   - 一旦确定了语言，它会将其存储在 `localStorage` 中，以便用户下次访问时保持偏好。
3. **动态切换**：`setLanguage` 函数允许用户在运行时切换语言。它会验证新语言是否受支持，然后动态导入相应的语言包文件，更新状态，并将新的语言代码写入 `localStorage` 和 HTML 的 `lang` 属性。

## 添加新语言的完整步骤

为系统添加一种新语言（例如德语 `de`）需要在后端和前端进行协调配置。

**Section sources**
- [lang.json](file://api/config/lang.json)
- [messages](file://src/messages)
- [LanguageContext.tsx](file://src/contexts/LanguageContext.tsx)

### 1. 在后端注册语言
编辑 `api/config/lang.json` 文件，在 `supported_languages` 对象中添加德语条目。
```json
{
  "supported_languages": {
    ...
    "de": "German (Deutsch)"
  },
  "default": "en"
}
```

### 2. 创建前端语言包
在 `src/messages` 目录下创建一个新的 `de.json` 文件，并将所有界面文本从英文翻译成德文。
```json
{
  "common": {
    "appName": "DeepWiki-Open",
    "tagline": "KI-gestützte Dokumentation"
  },
  "home": {
    "welcome": "Willkommen bei DeepWiki"
  }
}
```

### 3. 确保前端正确使用
- **使用 `useLanguage` 钩子**：在任何需要显示多语言文本的组件中，都应通过 `useLanguage()` 钩子来获取 `messages` 对象，而不是使用硬编码的文本。
- **动态加载**：`LanguageContext` 会自动处理 `de.json` 文件的动态加载，无需额外配置。

## 语言配置与内容生成

系统通过一个关键的设计原则来确保生成内容的语言与界面语言一致：**语言配置的统一性**。

- **单一来源**：无论是前端界面还是后端生成的维基文档，其语言选择都源于同一个配置源——`lang.json` 文件中的 `supported_languages`。
- **同步机制**：当用户在前端通过 `LanguageProvider` 切换语言时，这个选择不仅改变了界面显示，也隐含地决定了后续所有生成请求所使用的语言。后端的生成逻辑会读取 `lang.json` 配置，并根据请求中携带的语言偏好（通常通过API参数或上下文传递）来生成相应语言的文档。
- **一致性保证**：由于前后端共享同一套语言定义和默认设置，系统能够保证用户看到的界面语言与生成的维基文档语言始终保持一致，为用户提供无缝的多语言体验。

## 结论
本系统的多语言支持机制设计精良，通过清晰的职责分离和强大的容错能力，实现了高度的灵活性和稳定性。后端的 `lang.json` 和 `load_lang_config()` 函数提供了可靠且可扩展的配置基础，而前端的 `LanguageContext` 则提供了流畅的用户体验。通过遵循添加新语言的标准步骤，可以轻松地将系统扩展到支持更多语言，从而服务于更广泛的用户群体。
