## 与容器化部署的差异

| 特性 | 脚本化部署 (`run.sh`) | 容器化部署 (`docker-compose.yml`) |
| :--- | :--- | :--- |
| **环境管理** | 手动配置宿主机的Python和Node.js环境 | 由Docker容器自动提供隔离环境 |
| **依赖安装** | 需手动运行 `uv sync` 和 `yarn install` | 在构建镜像时自动完成 |
| **前后端启动** | 需手动执行 `yarn build` 和 `yarn start` | 由Docker Compose统一管理 |
| **环境变量** | 依赖本地的 `.env` 文件 | 可通过 `docker-compose.yml` 或 `.env` 文件注入 |
| **适用场景** | 开发调试、快速本地测试 | 生产部署、CI/CD、环境一致性要求高的场景 |
| **复杂度** | 较高，需要管理多个步骤 | 较低，`docker-compose up` 一键启动 |

## 结论
`run.sh`脚本为开发者提供了一种直接、灵活的非容器化部署方案。它通过`uv run -m api.main`命令直接启动FastAPI服务，是开发和调试阶段的理想选择。用户需要手动管理Python和Node.js环境、安装依赖、构建前端并配置环境变量。虽然流程比容器化部署更繁琐，但它提供了对运行环境的完全控制，便于进行调试和定制。对于生产环境，推荐使用Docker进行部署以保证环境的一致性和可移植性。
